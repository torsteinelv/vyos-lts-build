# Qualification configuration - a representative, non-topology-specific
# set of VyOS `set` commands, applied in order via `configure` + this
# file's lines + `commit`. Proves that these config trees still parse
# and commit on the pinned build - not a functional test of every
# feature (VyOS's own upstream smoketest suite, run separately in the
# `smoketest` job, already covers a lot of that).
#
# Currently minimal (interfaces + a firewall rule) - broadening this to
# cover more general VyOS feature areas (VLAN, NAT, WireGuard, VRRP,
# BGP, ...) is documented as future work in README.md. Each addition
# needs its syntax verified against a real boot first, same as this one:
#
# The first real run of the strict candidate-config-test gate caught a
# genuine syntax error here: "state established 'enable'" /
# "state related 'enable'" are rejected by this build ("Configuration
# path: ... is not valid") - the state-matching syntax has evidently
# changed on current VyOS vs. what was assumed when this placeholder was
# written. Dropped those two lines rather than guess the current correct
# syntax blind; if you need established/related matching, check
# `set firewall ipv4 name WAN-IN rule 10 ?` on a real running instance
# first. This is exactly the kind of thing the gate exists to catch.

set interfaces ethernet eth0 address 'dhcp'

set firewall ipv4 name WAN-IN default-action 'drop'
set firewall ipv4 name WAN-IN rule 10 action 'accept'
set firewall ipv4 name WAN-IN rule 10 protocol 'tcp'
set firewall ipv4 name WAN-IN rule 10 destination port '22'

# Source NAT (masquerade) - syntax taken from VyOS's own real smoketest
# config (vyos-1x smoketest/configs/nat-basic), not guessed.
set nat source rule 100 outbound-interface name 'eth0'
set nat source rule 100 source address '192.168.1.0/24'
set nat source rule 100 translation address 'masquerade'
